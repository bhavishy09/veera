🧭 How Vera Works — 3-Layer Architecture

PRD & Implementation Blueprint
1

Ingestion & Data-Driven Context Hub (`/v1/context`)

Vera is 100% data-driven. It operates on 4 explicit context streams: Category (tone, style, taboos, peer benchmarks for 5 verticals), Merchant (stats, active offers, cohort sizes), Customer (visit history, preferences, consent), and Triggers (internal dips, external compliance, research digests). Absolutely zero category logic is hardcoded.

2

Layer 1: Deterministic Decision Gatekeeper (`/v1/tick`)

Runs sub-millisecond ranking and anti-fatigue filtering:
• Silence Bar (0.35): Drops low-urgency triggers to avoid spam.
• Merchant Pacing Window (1 hr): Guarantees merchants never receive clustered messages.
• Anti-Spam Suppressions: Emits idempotent suppression keys so acted triggers are never repeated.

3

Layer 2: Grounded Gemini Composer & Strict Fallback

Prompts Google Gemini Flash with strict structured JSON schema. The model runs silent reasoning to pick the best single engagement lever, writes a WhatsApp-native message under 60 words, and guarantees exactly ONE clear CTA in the cta field. An anti-fabrication validator verifies that every number/date cited exists in the input context.

4

Layer 3: Multi-turn State Machine (`/v1/reply`)

Handles incoming replies: detects automated autoreplies to avoid infinite loops, transitions qualifying conversations to action upon receiving commitment, and immediately ends upon encountering hostile or opt-out messages.
